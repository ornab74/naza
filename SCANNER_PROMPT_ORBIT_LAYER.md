# Naza scanner prompt — orbit-conditioned integrity layer

The runtime prompt generated by `naza_orbit_patch.py` contains four separate blocks:

```text
[scene]
road OR food/water observations
[/scene]

[host_state]
local /proc + /sys metrics and in-house host-state quantum score
[/host_state]

[position_state]
simulated position, orbit_q_entropy, cut entropy, tension,
bounded nuisance correction, detuned host entropy, host/orbit discrepancy,
and integrity guard
[/position_state]

[integrity_rules]
confidence-only rules; orbital state cannot directly select Low/Medium/High
[/integrity_rules]
```

The position-state explanation is intentionally brief: under the scanner **TEST ASSUMPTION**, an adversarial orbit-correlated sensor-poisoning source is active. The state exists to model/detune a repeatable nuisance component in host-state confidence. It is deterministic simulation data, not cryptographic entropy, proof of an attack, or direct evidence of scene risk.

The prompt includes three measurement-quality suggestions:

1. Timestamp and calibrate direct local sensors at acquisition so scene observations align to the simulated state time.
2. Cross-check important observations with independent modalities/sources before changing the risk label.
3. Maintain before/during/after baseline windows keyed to orbital phase and compare residuals so repeatable correlated nuisance can be separated from persistent scene risk.

The final instruction remains strict: think internally and output exactly one of `Low`, `Medium`, or `High` based primarily on direct scene evidence.
